# Video Walkthrough Script — Darwix Voice Intelligence Suite

**Target duration:** 12–15 minutes
**Audience:** Assessment evaluators
**Tools to show on screen:** browser (localhost:3000 dashboard), terminal, VS Code / file browser

---

## Section 1 — System Overview (2 min)

Open `README.md` → "Architecture" section. Walk through the Mermaid diagram or point to `architecture.mermaid`.

> "The system has four main layers. At the bottom is the knowledge base — 16 real BFSI source documents chunked, embedded, and indexed in FAISS. Above that, the RAG service retrieves and reranks chunks based on the incoming customer query, then passes the result to Gemini Flash to generate a grounded, citation-bearing answer. The API gateway sits in the middle, connecting the Vapi voice platform to the RAG service and simultaneously feeding transcripts to the real-time insights engine. The React dashboard gives agents live visibility into call state, nudges, and retrieved facts."

Point to the 'Environment Notes' section:

> "In this build, no external API keys are wired — I have no route to Deepgram, Vapi, or Google's embedding API. So all the grounding and latency evidence you'll see is generated by offline fallbacks that are explicitly documented and independently reproducible — you can re-run every report without any keys."

## Section 6 — Error/Fallback Cases, Limitations, Production (2 min)

Open `evaluation/known_limitations.md`:

> "There are three categories of honest gap. First: no live recordings — I documented this clearly in the 'Environment Notes' section rather than hiding it. Second: offline retrieval — TF-IDF instead of Gemini embeddings, which I call out with the reason and the swap path. Third: real data-quality bugs I actually found and fixed — the 9 missing PDFs and 4 broken HTML scrapes."

Point to the "10x Scale" section:

> "At 10x load — 40 concurrent calls — the first thing that breaks is the in-memory CALL_STATES dict in the nudge service. The fix is Redis with per-call TTL. Second failure is fanout on Socket.IO without rooms. Both are solvable with standard infrastructure patterns — I've been specific about what breaks and how to fix it."

> "The production path is straightforward: wire four API keys, run the existing service stack, and every fallback I documented automatically upgrades to the production path. The same code, no architectural changes required."
